# Process identification technique
## SIPOC Diagram 
Suppliers (students, finance, IT, academic departments, funders), Inputs (applications, documents, fee rules, funding proofs), Process (capture → verify → quote/instruct → confirm payment → approve → create record → notify), Outputs (registered student record, student number, confirmation, accurate enrolment data), and Customers (students, sponsors, internal departments, regulators/funders) comprise the end-to-end boundaries of registration as defined by SIPOC. I made the handoffs where things break visible by mapping this in a single view (student → admissions intake; admissions → finance; finance → systems, for example). I agreed on who owns which outputs, defined upstream fixes (e.g., more explicit entry criteria on the portal decrease downstream verification rework), and tested the completeness and readiness of inputs using SIPOC (introducing a document checklist and validation rules). Additionally, it anchored measurement, giving each output a KPI and an owner.
